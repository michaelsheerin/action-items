# Action Items

A single editable table for Internal, Goldman, Uber, Claritev, and Paramount. The interface uses flat spreadsheet cells, regular-weight text, compact fonts, and the existing navy, blue, and slate headers. Task rows are white. The blank entry row at the end of each subsection is faded blue-gray. Status colors fill their cells, and overdue dates retain their red text. The table fills the available page width while preserving manual column resizing. Each account shows This Week first, including overdue actions. Remaining Items holds later and undated actions and starts collapsed. Click its header to expand or collapse that account. Expanded sections stay open during edits and filtering; reloading starts them collapsed again. Typing in a blank row starts and saves a record automatically.

## Open locally

Requires Node.js 20 or newer. Run `node serve.mjs` and open http://127.0.0.1:4173. Run `npm test` for domain and interaction regression checks.

## Publish on GitHub Pages

Publish `index.html`, `archive.html`, `hours.html`, `activities.html`, `app.js`, `core.js`, `store.js`, `columns.js`, `interactions.js`, `work.js`, `work-core.js`, `work-store.js`, `work-picker.js`, `quarter.js`, `styles.css`, `work.css`, `icon.svg`, and `.nojekyll` at the repository root. In Settings > Pages, choose Deploy from a branch, then main and /(root). No build command or third-party services are required. The test, server, and documentation files are optional for hosting.

## Records and autosave

Records save to IndexedDB in the current browser and site origin after each edit. The header confirms successful writes. A save failure keeps the edit on screen, shows a retry action, and offers an emergency backup. Browser tabs synchronize after edits; separate devices do not synchronize. Clearing site data removes this browser's records.

Use Data > Download JSON for a complete backup. Import merges by stable record ID and preserves existing edits by default. Select Update matching records to overwrite existing IDs deliberately. Import validates the full file before opening one transaction. No task records or credentials belong in this repository.

JSON backups now use version 3 and retain optional cell bolding and hyperlink display labels. Older backups remain supported. A CSV export retains the original ticket URL or ID and adds a final Link display text column when labels are present. CSV does not carry font formatting.

The migration JSON delivered separately contains the workbook's populated tasks, including completed and hidden rows. Import the file once on the published site. Archived rows keep their historical completion date unknown because the workbook did not record completion timestamps. Original sheet names and row numbers stay in each source reference. Status options are Urgent, Waiting, Scheduled, and Not Urgent. Existing records migrate automatically: Waiting and Scheduled take priority, followed by Urgent, then Not Urgent. The original classification stays in backup metadata. Existing due dates stay unchanged. New actions start without a due date, with status Not Urgent and owner Michael Sheerin.

Category completion includes active and archived categories for the selected account. Owner completion includes existing owners. Suggestions appear as selected text inside the textbox. Tab, Enter, Right Arrow, or leaving the field accepts the completion. Escape keeps the typed prefix. Backspace dismisses a suggested suffix before deleting typed text. New categories stay editable without a selection list. Only accepted completion text is saved; the typed prefix saves during entry.

Controls retain their DOM nodes across edits and filtering. Sorting and account/date regrouping wait until focus leaves the editable table, so a row never moves under an open dropdown or calendar. Incoming updates from other tabs wait until the current edit finishes. No delayed row rebuild interrupts the next field. A dedicated calendar button, Alt+Down, or F4 opens the native date picker. New actions retain a blank due date until a date is selected.

Search and status filters reveal matching Remaining Items automatically and hide accounts without matches. Clear the filter to return to the usual collapsed layout. Archive initially renders 50 records; Show more loads another 50. Search covers the entire archive regardless of the rendered limit.

Ticket entries accept IDs or HTTP/HTTPS links. Enter adds a line in Action Item. Notes support multiple lines with Shift+Enter. Tab and Shift+Tab move directly between fields. Ctrl+Alt+Up/Down moves within the same column across visible rows. Alt+Left/Right moves between fields. Ctrl+Enter (Cmd+Enter on Mac) starts another action in the current section. Alt+N starts a new action. Ctrl+K (Cmd+K on Mac) or / outside a field opens search. Enter in search focuses the first visible action. Escape clears search or leaves an editable field. The Shortcuts button, or ? outside a field, shows the keyboard reference. Dropdown arrows keep native browser behavior.

Select a cell and click B in the toolbar, or press Ctrl+B (Cmd+B on Mac), to toggle bold for that whole cell. Existing and new cells start with regular-weight text. Formatting an empty entry row does not create an action until content is entered, and the next blank row starts regular again. Bolding saves with the record and stays attached through sorting, account changes, and Archive.

Edit a ticket hyperlink with the link button in the toolbar, the pencil shown on hover in the ticket cell, or Ctrl+K (Cmd+K on Mac) while editing that cell. The editor separates Address or ticket ID from optional Display text. Leave the display text blank to show the original address. After setting a label, edit its text directly in the cell; the destination stays unchanged. Pasting a complete HTTP/HTTPS address replaces the destination and clears the old label. The open-link arrow always uses the saved destination. Use the editor to change or remove that destination. Labels participate in search, backups, import, and Archive.

Drag the right edge of any column header to resize. Double-click an edge to fit the visible records. Focus an edge and use Left/Right arrows for 10-pixel changes, or Shift+Arrow for 50-pixel changes. Widths save in this browser and apply to the action list and archive. Reset widths in the table footer restores the original layout.

## Activities and hours

Hours and Activities retain the shared Action Items navigation bar and navy column headers, with white table rows, light dividers, compact account labels, and no summary cards or colored account bars. The Hours toolbar contains week navigation; Activities contains search and a New activity button. Add row sits beside each account subtotal. Backup details and historical totals live under Data & backup. `work.css` keeps the simplified table layout and matches the shared navigation and column-header colors. Hours and Activities columns support drag resizing, keyboard resizing with Left/Right or Shift+Left/Right, and double-click autofit. Widths save separately for each page and persist across search, week changes, and reloads. Reset widths is available in Data & backup.

Hours and Activities use a separate IndexedDB database, `sheerin-work-log`, with activities, daily entries, historical balances, and row preferences. Existing Action Items records and settings stay in `sheerin-action-items`. Neither database sends private records to GitHub. Each area has its own JSON backup and import. Keep workbook files, private imports, and downloaded backups outside the public source directory.

Activities shows account sections with Opp ID, Stage, Activity Name, Personal Name, Description, and an artifact-presence checkbox. Descriptions stay on one line in the directory, with full text available in the edit form. Add or edit with the popup form. Account, opportunity, stage, and activity-name text inputs accept new values and offer clickable recommendations ranked by lifetime hours. Opportunity suggestions use the selected account; stage and activity-name suggestions also use the selected opportunity. Artifact URLs are not part of the activity model. Claritev is excluded for now.

Hours uses Monday through Sunday, with previous/next, a native date selector, and a This week shortcut. Each account starts with three blank activity rows. Activities already containing hours for the chosen week appear automatically, followed by blank entry rows. Add another activity adds a row. Choices rank by lifetime hours and display opportunity, personal name, stage, and the full description. CSS clips each label to the available column width, so widening the Activity column reveals more text. Dropdown width follows the same column. The activity/day records retain their IDs when a label expands. Search also covers full descriptions and activity names. Arrow keys and Enter select an option; Tab moves through day fields. Ctrl+Alt+Up/Down moves along the same day column. Alt+Left/Right changes week. Alt+N opens the activity form.

Each activity shows lifetime and current Oracle fiscal quarter hours before the daily fields. The displayed-week total follows Sunday at the right edge. Account and all-account sums follow the same day-first order. Oracle fiscal years begin June 1. The current quarter is labeled with its fiscal year and date range, independently of the displayed week. Input accepts zero to 24 hours with up to two decimal places. Blank clears the activity/day value; repeated edits replace that value rather than append hours. Row, account/day, and all-account/day sums update immediately. Duplicate activity choices are excluded within an account. Switching a chosen activity retains the former activity's saved hours and keeps a row for any hours in the displayed week.

Historical balances retain their original period and total, without invented daily dates. Lifetime totals include them. Historical quarters contribute to their matching quarter, while annual balances do not get allocated across quarters. Daily inputs are locked inside an activity's historical aggregate period to prevent double counting. Data & backup exposes the historical balance list. Import validates dates, IDs, hours, references, duplicate records, and historical overlaps before one atomic transaction. Stable IDs make repeated imports idempotent; existing corrections are preserved unless Update matching records is selected.

Browser tests cover recommendations, keyboard selection, row addition, immediate sums, daily persistence, week changes, activity editing, long descriptions, artifact toggles, historical locks, and repeat imports. Run `node --test core.test.js interactions.test.js work.test.js` for the automated suite.

## This Quarter's Hours

An expandable section below Hours entry lists activities with positive hours in the current Oracle fiscal quarter through today. Rows group by account. Monday-to-Sunday week columns cover elapsed weeks; the first and current weeks include only dates inside the quarter through today. Future-dated entries and previous quarters do not contribute to the quarter-to-date report. Each activity has a quarter total, with weekly and overall sums at the bottom. The report updates as daily entries change.

Quarter hours so far and Target so far appear below the table. Target equals the number of Monday-through-Friday dates from the quarter start through today, inclusive, multiplied by eight hours. This is a weekday target, with no holiday or leave deductions. The report shows the workday count and through date alongside the target.

Imported period-only balances are never distributed across invented weeks. A completed historical period wholly within the current quarter appears in a separate Historical column when present. The quarter table supports saved column widths, including new weeks added as the quarter progresses. Data & backup > Reset widths resets the entry and quarter tables. The section starts collapsed after reload.
